# Claude GitHub Actions research, 2026-09-09

This note records the research behind updating this repository's two Claude workflows. The comparison and run evidence describe the pre-update baseline. Findings use primary documentation and pinned action source; the implementation follow-up records the selected changes.

## Scope, tools, and limits

`--allowedTools` grants approval without prompting; `--tools` restricts available built-in tools. For the read-only review, use `--tools "Read,Grep,Glob"` plus those allowed tools and the one inline-comment MCP tool. `--strict-mcp-config` ignores other MCP configurations. `--setting-sources user` excludes project/local settings, and the action's SDK adapter explicitly supports that choice. These controls should accompany a precise prompt, rather than relying on a no-edit sentence alone. [CLI reference](https://code.claude.com/docs/en/cli-reference#cli-flags), [settings adapter](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/base-action/src/parse-sdk-options.ts).

Current model documentation confirms `claude-sonnet-5` and `claude-opus-5`. Sonnet 5 requires Claude Code 2.1.197 or later; Opus 5 requires 2.1.219 or later. Full model names avoid moving family aliases. [Model configuration](https://code.claude.com/docs/en/model-config#model-aliases).

`--max-turns` bounds agentic turns and errors when exhausted; it does not set a dollar budget. `--max-budget-usd` is a separate API-spend limit, including subagents on supported CLI versions. Do not describe it as a hard cap on subscription consumption. Recommendation: begin with kkb's 25-turn Sonnet automatic-review budget and an explicit job timeout, then tune from observed completion and cost. [CLI reference](https://code.claude.com/docs/en/cli-reference#cli-flags).

The reviewed source exposes no automatic successful-review checkpoint. GitHub concurrency can cancel running and pending reviews. Therefore a `synchronize` patch of only the immediately preceding push can omit changes whose earlier review failed or was canceled. This is an inference from the scope algorithm and cancellation semantics, not an observed missed defect. Recommendation: review the complete current PR initially. Add incremental scope only if measurements justify maintaining a last-successful reviewed SHA and handling force pushes and failure recovery. [GitHub concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency), [agent-mode preparation](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/modes/agent/index.ts).

## Authentication and trust boundaries

Model authentication and GitHub authentication are separate. The action accepts an Anthropic API key or Claude subscription OAuth token. `claude setup-token` generates a one-year token for CI. The official GitHub App exchanges GitHub OIDC for its own repository token, requiring `id-token: write`. Refreshing an expired Claude OAuth secret does not resolve a GitHub workflow-validation rejection. [Setup](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/docs/setup.md), [OAuth token generation](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token), [GitHub token exchange](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/github/token.ts).

Current source explicitly skips recognized workflow-validation failures and explains that new/changed workflow PRs begin working after merge. A skipped or green run is therefore insufficient proof that Claude reviewed a PR. Validate a real model result and expected output after the approved workflow reaches the default branch. [Validation handling](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/github/token.ts#L24-L53), [skip explanation](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/github/token.ts#L124-L137).

Job `permissions` scopes `GITHUB_TOKEN`, but the default Claude App token is separate. Its source defaults include write access for contents, pull requests, and issues. `additional_permissions` merges with those defaults. Thus `contents: read` in the job alone does not prove Claude's App cannot write code. Preserve the App identity and restrict tools for review; validate token scoping separately if strict API-level read-only contents access is required. [Default permissions and merge](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/github/token.ts#L69-L104), [identity behavior](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/docs/faq.md#why-are-my-comments-not-appearing-as-claudebot).

The action defaults to repository writers and rejects bot invocations unless configured. Prefer explicit trusted bot names over `allowed_bots: '*'`. For this public repository, retaining `pull_request`, skipping drafts and fork heads, and adding `ready_for_review`/`reopened` is a conservative initial contract. Ordinary fork PR workflows lack normal secrets; do not change to privileged `pull_request_target` merely to bypass that limitation. [Action access controls](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/docs/security.md), [GitHub PR event behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request).

The current action restores a fixed set of Claude configuration paths from the PR base before execution, preserving PR versions under `.claude-pr/`. `AGENTS.md` is not in that set. Consequently, restoring this site's base `CLAUDE.md` symlink to `AGENTS.md` does not independently restore the target's base contents. Treat changed guidance as review data and choose explicitly which revision supplies reviewer authority. Package scripts and executable project configuration also remain at the PR head; omitting Bash from automatic review avoids executing those project commands. [Restore implementation](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/github/operations/restore-config.ts), [security limits](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/docs/security.md#which-files-come-from-the-base-branch-on-pull-requests).

Inline comments with `confirmed: true` bypass the new comment-classification buffer. The classifier checks whether unconfirmed comments are probes, not whether a defect is correct. Without an API key, including OAuth-only runs, its source falls back to posting unconfirmed candidates. Do not mistake that feature for an independent correctness review. [Classifier implementation](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/src/entrypoints/post-buffered-inline-comments.ts).

Optional future authentication: current v1 also supports Anthropic workload identity federation, removing a static API key through Console-managed federation rules. This changes account setup and billing/authentication choices; it is not needed for the workflow migration. [Federation setup](https://github.com/anthropics/claude-code-action/blob/19dda84776b3518d98b8798e591daee763049ed3/docs/setup.md#workload-identity-federation).

## Recommended update boundary

1. Repair model authentication and migrate both beta workflows to the same reviewed v1 pin and CLI inputs.
2. Make automatic review a bounded Sonnet pass over the full PR, with prior-feedback context, introduced-defect findings, inline output, and silence when clean. Use explicit PR event gates and concurrency.
3. Keep mention-driven assistance separate. Its ability to edit or execute project commands is a different contract from automatic review. Use this repository's commands and guidance rather than copying kkb's script names.
4. Defer manual Opus review, incremental review state, and a plugin migration until there is a specific need. Do not copy kkb's entire orchestration solely for consistency.
5. Validate the post-merge auth path, one real review, repeated-push behavior, draft/ready events, and deliberate no-finding behavior. Treat these as workflow acceptance checks, not a request to change production or introduce unrelated CI.

## Proposed rollout for discussion

First migrate both workflows and refresh the existing OAuth credential through the user's normal secret-management route. Preserve separate automatic-review and mention-assistant responsibilities. Use a current reviewed v1 SHA rather than copying kkb's older review pin or moving mention tag.

For automatic review, carry over Sonnet, the narrow finding policy, prior-feedback context, inline publication, explicit PR-head checkout, draft/fork gates, concurrency, and tool restrictions. Prepare a bounded full merge-base-to-head patch on every eligible event. Start with 25 turns and a 15-minute job timeout as proposed operating values, then adjust using actual completion evidence. Stop explicitly if the patch/history limit or model limit prevents a complete review.

Defer kkb's manual Opus job unless a separate deep-review action is useful now. If both modes are desired, share patch/history preparation rather than duplicating most of kkb's 620-line workflow. Do not add persistent incremental-review state solely to match kkb. Full-PR review is simpler and recovers naturally after failed or canceled runs.

Implementation acceptance should check workflow syntax and supported inputs locally, then verify actual execution once the approved workflow is on the default branch. Confirm an inline finding can publish, a clean review completes silently, subsequent pushes consult prior feedback, and drafts/forks skip deliberately. These are future implementation checks; no workflow dispatch, credential mutation, commit, or GitHub write occurred during this research.

## Implementation follow-up

The selected update migrates both workflows to action `v1.0.220` at the reviewed SHA and pins checkout v6. [Automatic review](../../.github/workflows/claude-code-review.yml) uses Sonnet 5, 25 turns, a 15-minute timeout, full-PR scope, prior discussion and thread resolutions, and inline-only findings. It prepares inputs outside the PR tree, reads repository guidance from the base revision, and stops if the patch exceeds 1 MiB or history exceeds 512 KiB or any 100-item connection. Both the job token and separate Claude App token request read-only contents access; the App retains pull-request write access for inline findings. A step summary distinguishes completed execution from a workflow-validation skip.

[Mention-driven assistance](../../.github/workflows/claude.yml) retains its existing triggers and editing role, uses Opus 5 with 25 turns and a 15-minute timeout, and approves this site's install/build/test/typecheck/lint/format-check commands. `CLAUDE.md` remains the existing symlink. Manual Opus review, persistent incremental state, and a separate CI workflow remain deferred.

Local validation passed actionlint 1.7.12, Bash syntax checks, supported-input checks against the pinned action definition, and temporary Git/API fixtures covering full-PR scope across multiple commits, an advanced base branch, base-revision guidance, resolved feedback, incomplete connections, missing PR data, oversized inputs, and checkout mismatch. The exact history query also succeeded against existing site PR 20 through a read-only API call. No model run or comment publication was performed as part of these local checks.

The OAuth secret still needs a fresh CI token. End-to-end review and mention-assistant verification remain pending until authentication is repaired and the approved workflow is available on the default branch. Workflow syntax success or a validation skip is not evidence that Claude reviewed a PR.
