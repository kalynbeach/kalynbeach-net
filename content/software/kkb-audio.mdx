Sound software breaks down when file I/O, garbage collection, or interface updates bleed into the audio callback. `kkb-audio` isolates a single portable Rust render core from host concerns so the same engine runs in a browser `AudioWorklet` through fixed-memory WebAssembly and natively on macOS, while each host owns its own files, devices, and lifecycle.

The engine compiles signal graphs into explicit execution plans, verifies partition-independent rendering across callback sizes, avoids heap allocations on the render path, and streams decoded audio across bounded lock-free or recycled-buffer channels. Each milestone ships with a written evidence record documenting what was verified and where the boundaries remain; the engine, player, and lab are actively developed experimental software rather than a finished consumer release.

## WavePlayer

An experimental local audio player built on the `kkb-audio` engine and live at [kkb-audio.vercel.app](https://kkb-audio.vercel.app). It plays local WAV (PCM16, PCM24, float32) and Rust-decoded MP3 files entirely in the browser with nothing uploaded, handles 44.1 to 48 kHz conversion, and supports preview-and-commit seeking, A/B loop regions, an independent full-track source waveform overview, and a WebGPU P31 phosphor XY oscilloscope.

## Engine lab and proofs

Alongside WavePlayer, the app includes an interactive learning lab for inspecting the compiled oscillator graph, sample-timed gain events, and render-partition comparisons, plus standalone browser proofs for the bounded PCM transport and compiled execution plan.
